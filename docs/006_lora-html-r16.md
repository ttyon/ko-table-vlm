# 006 LoRA SFT: Qwen3.5-2B, HTML 출력, rank 16 (2주차)

## 질문
합성 표 3,000장으로 2B를 LoRA 미세조정하면 얼마나 좋아지는가? 그 개선이 실제 문서로 전이되는가?

## 판단 근거 — 설정을 이렇게 정한 이유
| 설정 | 값 | 이유 |
|---|---|---|
| 모델 | Qwen3.5-2B (bf16) | zero-shot이 이미 Docling보다 좋아(005) 출발점이 좋음. 2B는 Mac에서 학습 1시간대 → 여러 번 반복 가능 |
| 방법 | LoRA (full fine-tuning X) | 메모리·시간. 출력 형식과 구조 규칙을 배우는 과제라 소수 파라미터로 충분하다고 판단 |
| rank / alpha | 16 / 32 | 형식 학습에는 8이면 충분하다는 경험칙이 있지만, 구조 추론도 필요해 한 단계 여유. rank 비교는 011 |
| lr / iter | 1e-4 / 3,000 (≈1 epoch) | LoRA 표준 범위. 데이터가 정형적이라 1 epoch면 수렴할 것으로 예상 |
| `--train-on-completions` | on | 프롬프트·이미지 토큰이 아닌 정답 HTML에만 loss |
| 출력 형식 | 정규화 HTML | 평가 형식과 동일 → 후처리 없이 채점. 대안 OTSL은 008에서 비교 |

## 학습
- 81분 (1.6초/iter), 피크 메모리 **13.1GB**, 학습 파라미터 16.8M (0.76%)
- val loss: 0.0192 (250) → 0.0073 (500) → … → **0.0034 (2250, 최저)** → 0.0050 (3000)
- 토큰 정확도 99.8% — HTML 태그 토큰이 대부분 예측 쉬워 **loss는 둔감한 지표**. 판단은 TEDS로.

## 해석
1. **합성 분포 안에서는 큰 개선**: 학습 전 0.94 → 0.99, 27B도 넘어섬. ood(처음 보는 스타일)에서도 유지 → 스타일을 외운 것은 아님.
2. **실제 문서에서는 구조만 전이됐다**: 병합 셀 재현율 0.44→0.68, TEDS-S +0.015, CER 개선. 그러나 TEDS는 같고 샘플별로 오히려 27패. 구조 개선을 텍스트·헤더 오류가 상쇄.
3. **합성→실제 격차는 "구조"보다 "실제 어휘·헤더 패턴"에 있다** — 007의 실패 분석과 002의 미리보기 차이가 같은 지점을 가리킴.
4. **지연 역설**: 출력 토큰이 27% 줄었는데 지연은 늘었다 (5.3→7.9초). 어댑터를 기본 가중치에 합치지(fuse) 않아 매 토큰 추가 연산을 하기 때문으로 추정 → 후속 과제.
