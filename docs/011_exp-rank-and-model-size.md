# 011 실험: LoRA rank (8/16/32)와 모델 크기 (2B vs 4B) (3주차)

## 질문
1. LoRA 용량(rank)을 바꾸면 성능이 달라지는가? 16이 적당한가?
2. 모델을 2B → 4B로 키우면 실제 문서 성능이 오르는가? 속도 대가는?

## 판단 근거
- 006에서 rank 16을 고른 근거는 경험칙뿐이었다 → 실측으로 확인할 필요.
- 005에서 27B가 실제 문서에서 압도적이었다 → "크기가 답인가?"를 중간 크기(4B)로 확인. 27B LoRA는 학습 시간·메모리 부담이 커 4B를 선택.
- 기준 설정은 009에서 가장 좋았던 **혼합 데이터 + 1,500 iter** (학습 시간도 절반이라 여러 조건 비교에 유리).

## 고려한 대안
| 대안 | 판단 |
|---|---|
| rank 실험을 원본 데이터(006)로 | 실제 문서에서 더 좋은 설정 위에서 비교해야 최종 모델 선택에 쓸모 → 혼합 데이터 사용 |
| 4B를 bf16으로 | 4B bf16 MLX 버전 대신 공개된 **4-bit 버전(QLoRA)** 사용 — 메모리·속도 현실적. 단 **2B(bf16)와 정밀도가 달라 순수한 크기 비교는 아님** (한계로 명시) |
| 27B LoRA | 시간·메모리 부담. 증류(012 제안)가 더 현실적 |

## 방법
- 공통: 혼합 데이터(원본 3,000 + 보강 3,000), lr 1e-4 고정, batch 1, 1,500 iter, alpha = 2×rank
  - mlx-vlm 구현 확인: `scale = alpha / rank` = 2.0으로 **모든 rank에서 같다** (`adapter_config.json`) → rank 간 비교에서 스케일 차이는 없음.
- r16은 009b 혼합 학습의 1,500 iter 체크포인트를 그대로 사용 (같은 데이터·같은 스텝).
- 평가: val·test·ood 앞 100, real 50, + dev 17개 잘림 검사 (009c 규칙).

## 해석
1. **평균을 결정한 것은 "가끔 일어나는 반복 붕괴"였다.**
   - r8·4B는 중앙값과 샘플별 승수로는 r16보다 약간 낫다. 그런데 표 1개에서 반복 붕괴(TEDS 0.01·0.04)가 나서 평균이 0.02~0.03 떨어졌다. 붕괴를 뺀 평균: r8 0.931, 4B 0.927, r16 0.936.
   - 즉 **일반적인 품질은 r8~r16, 2B~4B 사이에 거의 차이가 없고**, 차이는 **안정성(붕괴 여부)** 에서 났다. n=50에서 붕괴 1건 차이는 우연일 수 있다.
2. **rank 32는 이 설정에서 불안정**: 파라미터가 많을수록 고정 lr(1e-4)에서 체크포인트 간 출렁임이 커졌다(val loss 2배 점프). rank를 키우려면 lr을 낮추거나 cosine decay가 필요해 보인다 — 용량 부족이 아니라 **최적화 설정 문제**로 판단.
3. **4B(4-bit)는 2B(bf16)보다 낫지 않았다.** 학습 전 실제 문서 점수도 4B가 오히려 낮다(0.887 vs 0.896). 표 인식처럼 "형식+시각 판독" 과제에서는 2B→4B 크기 증가보다 **데이터(009, +0.038)의 효과가 훨씬 컸다.** 단, 4-bit 양자화가 섞여 있어 순수 크기 효과는 분리되지 않았다.
4. 속도: 4B는 학습 1.8배, 추론 1.5배 느리다. 메모리는 4-bit라 오히려 적다.

## 결론
- **rank 16, 2B(bf16) 유지.** 근거: 평균·안정성 모두 최고, 학습·추론 가장 빠름. r8도 거의 대등하므로 어댑터 크기가 중요하면 r8도 선택지.
- **다음으로 성능을 올릴 레버는 모델 크기가 아니라 (a) 반복 붕괴 대응과 (b) 데이터**다.
  - (a) 잘림 감지 → 재시도/대체 경로 (012에서 오프라인 시뮬레이션)
  - (b) 27B를 교사로 쓰는 실제 문서 증류 (012 제안)
