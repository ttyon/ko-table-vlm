# 012 종합 결론 (1~3주차, 2026-11-19)

> **후속 갱신 (014)**: 다른 기관 문서(test-real-2)에서는 아래 최종 2B 모델이 0.805로 **학습 전 2B(0.900)보다 낮았다** — 이 문서의 결론은 국회예산정책처형 문서에 한정된다. 원인과 다음 단계는 [014](014_eval-other-institutions.md).

## 한 문장 요약
**합성 데이터만으로 학습한 2B VLM이 실제 한국어 예산 문서 표에서 Docling을 크게 앞섰고(0.773 → 0.956), 실패 분석에 근거한 데이터 보강·체크포인트 선택·입력 해상도 조정으로 단계적으로 개선했지만, 같은 조건의 27B zero-shot(0.985)에는 아직 미치지 못한다.**

## 가장 중요한 교훈 5가지
1. **합성 테스트만 보면 틀린 결론을 낸다.** 합성에서는 LoRA가 27B를 넘고(0.986 vs 0.951), OTSL이 효율적으로 보였다. 실제 문서 50개가 두 결론을 모두 뒤집었다.
2. **실패를 유형별로 세면 다음 실험이 정해진다.** "구조는 전이, 어휘는 전이 안 됨"(007) → 데이터 보강(009)이 가장 큰 개선을 냈다.
3. **마지막 체크포인트를 믿지 말 것.** 반복 붕괴는 합성 val에서 보이지 않았다. 정답 없는 실제 데이터의 "잘림 비율"이 값싼 선택 기준이 됐다.
4. **평균은 드문 붕괴에 지배된다.** rank·모델 크기 비교의 차이 대부분은 표 1~3개의 반복 붕괴였다 → 중앙값·최저값·잘림 비율을 함께 봐야 한다. 시스템 차원에서는 "잘리면 Docling으로 대체" 정책이 손실 대부분을 복구했다 (011 시뮬레이션: 0.913→0.932 등).
5. **비교는 같은 조건에서.** 해상도 확대 후 "2B가 27B를 따라잡았다"고 볼 뻔했지만, 27B도 같은 이득을 얻었다.

## 한계 (정직하게)
- **실제 문서 50개, 같은 기관 2개 문서.** 보강 데이터 설계와 해상도 비교 모두 이 세트의 실패를 보고 정했다 → 다른 기관 문서에서는 개선 폭이 작을 수 있다.
- 실제 문서 정답 초안이 Docling(PDF 모드)에서 왔다. 50개 모두 구조를 이미지와 대조했지만 놓친 오류가 있을 수 있다.
- **자간 헤더 라벨 불일치**: 보강 템플릿이 `증 감`처럼 띄어 쓴 정답을 넣어 실제 라벨 규칙(`증감`)과 어긋났다 → 공백 무시 점수를 함께 보고.
- 4B는 4-bit, 2B는 bf16 — 크기 비교에 양자화가 섞여 있다.
- 지연은 어댑터를 합치지(fuse) 않은 상태 기준 — LoRA가 출력 토큰은 줄였는데 학습 전보다 느렸다(5.3→7.9초).

## 4주차 이후 제안 (우선순위)
1. **다른 기관 실제 문서로 test-real 확장** (통계청·지자체·스캔본) — 지금 결론이 일반화되는지 확인. 가장 중요.
2. **27B → 2B 증류**: test-real과 다른 문서 페이지를 27B(1280)로 라벨링해 실제 분포 학습 데이터 확보 — 남은 격차(0.029)를 줄일 가장 유력한 방법.
3. **반복 붕괴 방지**: 스트리밍 중 n-gram 반복 감지 → 조기 중단·재시도 (지금은 4,096 토큰까지 ~70초 낭비).
4. **고해상도 학습 데이터** (글자 작게, 1280~1600 렌더) + 자간 헤더 라벨 규칙 수정 (CSS letter-spacing, 정답은 붙여 쓰기).
5. **어댑터 fuse 후 지연 재측정**, lr cosine decay로 rank 32 재시도.
