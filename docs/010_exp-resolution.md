# 010 실험: 입력 해상도 (3주차)

## 질문
같은 모델에 입력 이미지를 더 크게(또는 작게) 넣으면 정확도와 속도는 어떻게 변하는가?

## 판단 근거
- VLM 노트 `VLM/005`: Qwen 계열은 **LLM 토큰 1개 ≈ 32×32 픽셀**. 이미지가 작으면 글자 하나가 한 토큰보다 작아져 판독이 어려워진다.
- 실제 표 이미지는 PDF를 2배(약 144 DPI)로 렌더링해 잘라낸 것이라 **긴 변 평균 816px**, 본문 글자 높이가 20px 안팎이다. 합성 데이터(평균 850px)와 비슷하지만 글자가 더 작고 빽빽하다.
- 007의 실패 중 유사 글자 혼동(`수납`→`수남`, `관유물매각대`→`관계물량대`)은 해상도 부족 신호일 수 있다.
- 비용은 이미지 토큰(prefill)만 늘고, 출력 토큰(decode, 지연의 대부분)은 그대로 → **싸게 시도할 수 있는 개선**.

## 고려한 대안
| 대안 | 판단 |
|---|---|
| 해상도별로 데이터를 새로 만들어 재학습 | 학습 4회 = 5시간 이상. 먼저 추론만으로 효과가 있는지 확인 |
| PDF를 3배로 다시 렌더링 | 실제로 정보가 늘어나는 정석 방법이지만, 검출·라벨 재작업 필요 → 우선 리사이즈(확대)로 효과 크기를 본다 |
| **(선택) 같은 이미지를 긴 변 640/960/1280/1600으로 리사이즈** | 확대는 새 정보가 없지만, 글자당 패치 수가 늘어 VLM이 읽기 쉬워지는지 확인 가능 |

## 방법
- 모델: 현재 최고 설정 **2B LoRA r16, 혼합 데이터, 1,500 iter** (009) — 학습은 원래 해상도(≤1280, 평균 ~800)로 함.
- `scripts/make_resized.py`로 test 앞 50·real 50을 긴 변 640/960/1280/1600에 맞춰 리사이즈 (축소 LANCZOS, 확대 BICUBIC). 정답 HTML 동일.
- 공정성 확인: 같은 1280/1600 이미지로 **Docling과 27B도** 재측정.

## 해석
1. **입력 확대만으로 실제 문서 +0.020~0.025** — 재학습 없이, 지연 +0.2~0.6초. 3주차 실험 중 비용 대비 효과가 가장 컸다.
2. 효과는 **글자가 작은 실제 문서에서 크고**, 합성 test에서는 960 이후 거의 평평 (0.982~0.985). 합성 이미지는 글자가 상대적으로 커서 이미 충분하다.
3. 개선 내역: CER 0.132→0.081, 병합 셀 0.84→0.86 — 주로 **글자 판독 개선**. 007의 "유사 글자 혼동" 가설과 맞는다.
4. **27B도 같은 이득을 얻는다** (0.962→0.985). 그래서 2B와 27B의 격차는 해상도를 맞추면 오히려 그대로(0.026→0.029). "작은 모델이 따라잡았다"고 말하려면 같은 조건 비교가 필수였다 — 공정성 확인을 하지 않았으면 "2B 1600 = 27B"라는 잘못된 결론을 낼 뻔했다.
5. Docling은 변화 없음 — OCR·구조 모델이 내부적으로 해상도를 정규화하기 때문으로 보인다.
6. 1600에서 반복 붕괴 1건 → 해상도를 무작정 올리는 것도 위험. 학습 해상도(≤1280)와 너무 다르면 분포 이탈 가능.

## 주의
- 해상도는 **test-real 결과를 보고** 비교한 것이다. 최종 설정을 정할 때는 합성 test가 960 이상에서 평평하고(=손해 없음), dev 잘림 검사를 통과하는 **1280**을 택하는 것이 test-real에 덜 맞춘 선택이다.
- 확대는 새 정보를 만들지 않는다. 정석은 PDF를 더 높은 DPI로 렌더링하는 것 (후속 과제).

## 결론
- **추론 시 긴 변 1280으로 확대**를 기본으로 채택 (학습 해상도 상한과 같음, 붕괴 없음).
- 다음에는 **학습 데이터도 고해상도로** 만들어(합성 글자 크기 축소 + 1280~1600 렌더) 재학습하는 것이 자연스러운 다음 실험.
