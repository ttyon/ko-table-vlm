# 017 실험 A0: 학습 시퀀스 길이 제한(max_seq_length)만 바꾸기

## 질문
학습 샘플의 8~18%가 2,048 토큰에서 잘려 학습됐다(015). 이 잘림이 014의 반복 붕괴(긴 표에서 같은 행을 끝없이 생성) 원인인가?

## 판단 근거
- 잘린 샘플은 가장 긴 표들이고, 끝(`</table>`과 종료 토큰) 없이 학습됐다 → "긴 표는 끝나지 않는다"를 배웠을 수 있다.
- 반복 붕괴가 30행 이상 표에서만 일어났다(014) — 증상이 맞아떨어진다.
- 원인을 가르려면 **다른 건 전부 그대로 두고 이것만** 바꿔야 한다.

## 방법
기존 최종 모델(009c)과 데이터(혼합 6,000)·스텝(1,500)·lr(1e-4 고정)·seed·rank 모두 동일, `--max-seq-length 2048 → 6144`만 변경. 평가는 최종 추론 설정(입력 1280)으로 같은 세트.
학습 중 27B 라벨링이 GPU를 같이 써서 학습 시간은 비교하지 않는다(피크 메모리 17.6GB — 긴 시퀀스 때문에 13.1GB에서 증가).

## 결과
| 세트 | 기존 최종 (2048) | **A0 (6144)** |
|---|---|---|
| test (합성, 100) | **0.980** | 0.972 |
| ood (100) | 0.991 | 0.990 |
| test_v3 (합성 긴 표, 100) | 0.803 | 0.819 |
| test-real (50) | **0.956** | 0.929 |
| test-real-2 (15) | 0.805 | **0.857** |
| 스캔 모사 test-real | 0.941 | 0.949 |
| 스캔 모사 test-real-2 | **0.853** | 0.837 |
| 라벨 없는 실제 dev 잘림 (59) | 8 | 8 |

(A0 test의 첫 측정에서 26개가 서버 준비 전 요청으로 503 오류 → 오류 건만 재실행한 값. 016 "계획 대비 변경" 참고.)

## 해석
1. **잘림을 고쳐도 반복 붕괴는 그대로였다** (dev 잘림 8 → 8, test_v3 잘림 7% 유지). 잘림은 주된 원인이 아니었다.
2. 다른 기관 문서는 +0.052, 국회예산정책처 문서는 −0.027로 방향이 엇갈린다 — 단일 seed·체크포인트 선택 없이 한 번 학습한 결과라 이 크기의 차이는 노이즈 범위로 본다.
3. 결론: **"긴 표를 본 적이 없다"는 데이터 분포 문제가 핵심**이고, 시퀀스 길이는 긴 표를 학습시키려면 필요한 전제 조건일 뿐이다 → B(v3 데이터)에서 확인 (018).

## 그래도 고친 이유
v3 데이터는 2,048로는 57%(1,704/3,000)가 잘린다(016). 긴 표를 넣는 실험에는 6,144가 필수다. 이후 모든 학습은 6,144.
