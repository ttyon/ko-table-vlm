# 005 기준선: Docling · 2B zero-shot · 27B zero-shot (1주차)

## 질문
미세조정 전에, (1) 기존 파이프라인, (2) 학습 전 소형 VLM, (3) 큰 VLM은 각각 어느 수준인가?

## 판단 근거 — 왜 이 세 가지인가
| 기준선 | 답하려는 질문 |
|---|---|
| **Docling** (TableFormer ACCURATE + macOS Vision OCR ko/en) | "VLM이 기존 문서 파이프라인보다 나은가?" — 오픈소스 문서 변환의 사실상 표준 |
| **Qwen3.5-2B zero-shot** | "LoRA로 얻은 개선이 얼마인가?" — 학습 효과만 분리하는 기준 |
| **Qwen3.8-27B zero-shot** (이미 서빙 중) | "작은 모델 미세조정 대신 큰 모델을 쓰면 되지 않나?" — 크기로 해결되는지 |

고려했지만 뺀 것: 상용 API(GPT/Claude/Gemini) — 비용·재현성, 그리고 이 프로젝트의 관심은 로컬 실행.

## 방법
- 같은 프롬프트(`prompts.py` v1), temperature 0, max_tokens 4096, 동시 2요청.
- **실행 개수**: Docling은 test·ood 300개 전체, 2B는 앞 100개, 27B는 표당 ~35초라 **앞 50개**.
  → 비교표는 **모든 시스템을 같은 앞 50개로 다시 채점**한 값 (`evaluate --limit 50`). real은 50개 전체.
- 27B를 100→50으로 줄인 이유: 100+100+50개면 GPU를 ~5시간 점유해 3주차 실험 전체가 밀림. 기준선은 순위 파악이 목적이라 50개로 충분하다고 판단.

## 해석
1. **VLM이 Docling보다 확실히 낫다** — 학습 안 한 2B조차 실제 문서 TEDS +0.12. Docling의 약점은 병합 셀(재현율 0.43)과 OCR(`△`→`A`, `-` 누락), 그리고 표 검출 실패(real 8% 무효).
2. **모델 크기의 효과가 실제 문서에서 특히 크다** — 합성에서 27B는 2B보다 +0.015지만, 실제 문서에서는 **+0.066**. 큰 모델은 실제 문서의 다양한 어휘·레이아웃을 이미 알고 있다.
3. 27B의 실제 문서 오류는 62%가 "구조는 맞고 글자만 틀림"이고, 그 대부분이 자간 헤더 띄어쓰기(`구분`→`구 분`) — 공백 무시 시 0.971.
4. 대가는 지연: 27B는 Docling의 27배, 2B의 4배.
