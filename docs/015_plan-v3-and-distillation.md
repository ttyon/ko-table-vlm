# 015 사전 등록: 4주차 실험 계획 (생성기 v3 + 27B 증류)

> **이 문서는 test-real-3을 만들기 전에 작성·커밋했다.** 새 평가 세트를 본 뒤 설계를 바꾸지 않기 위해, 무엇을 바꾸고 무엇으로 판단할지를 미리 고정한다.
> 작성: 2026-11-19. 이후 계획에서 벗어난 점은 결과 문서에 "계획 대비 변경"으로 따로 적는다.

## 배경
1. 014: 최종 2B 모델이 다른 기관 문서(test-real-2)에서 0.805로 학습 전(0.900)보다 낮았다. 원인은 30행 이상 표의 반복 붕괴, 목록·문장형 표 약점.
2. **새로 발견한 학습 설정 문제**: `mlx_vlm.train`의 `--max-seq-length` 기본값이 **2048 토큰**이고, 넘는 샘플은 **뒤를 잘라서** 학습한다 (`trainer/vlm/cross_entropy/runtime.py`).
   토크나이저로 실측한 결과 학습 샘플(이미지 토큰 + 프롬프트 + 정답) 중 **원본 8.4%, 보강 17.8%, 혼합 13.1%가 2048을 넘었다** — 가장 긴 표들이 **끝(`</table>`과 종료 토큰) 없이** 학습됐다.
   → "긴 표는 끝나지 않는다"를 배웠을 가능성이 있고, 014의 반복 붕괴와 증상이 일치한다. 006~011의 모든 학습이 이 상태였다 (내 설정 확인 누락).
   test-real-2의 긴 표 정답은 최대 2,805 토큰 + 이미지 최대 ~1,600 토큰 → **6,144**로 올린다.

## 데이터 분리 규칙 (겹치지 않게)
| 묶음 | 용도 | 규칙 |
|---|---|---|
| test-real (국회예산정책처 2문서) | 평가 | 기존 그대로 |
| test-real-2 (통계청·복지부·행안부 3문서) | 평가 | 기존 그대로. **v3 설계에 쓰지 않는다** (설계는 아래 "축" 목록으로 고정) |
| **test-real-3 (새 기관 2곳 이상)** | **최종 평가 1회** | 만든 뒤 **최종 모델을 고를 때까지 어떤 모델로도 채점하지 않는다** |
| **증류 풀** (위 문서들과 겹치지 않는 문서) | 학습 (27B 가짜 정답) + 라벨 없는 선택용 dev | test 문서와 **문서 단위로 분리** |

## 실험 (각각 하나씩만 바꿈)
| ID | 바꾸는 것 | 데이터 | iter / lr | seed | 비교 대상 |
|---|---|---|---|---|---|
| **A0** | **max_seq_length 2048 → 6144만** | 혼합(html_mix) | 1,500 / 1e-4 고정 | 0 | 기존 최종(009c) — 같은 데이터·스텝 |
| B | + 생성기 v3 데이터 | 원본 + 보강 + **v3** | 3,000 / 1e-4 cosine decay, warmup 100 | 0, 1 | A0 |
| C | + **27B 증류 데이터** | B 데이터 + 증류 | 3,000 / 동일 | 0, 1 | B |

- seed 2개: 실제 문서 세트가 15~50개라 차이가 노이즈인지 확인하기 위함. 보고는 seed 평균 + 각각.
- LoRA r16, alpha 32, dropout 0.05, batch 1, `--train-on-completions`, grad checkpoint는 기존과 동일.

## 생성기 v3에 넣을 축 (지금 고정, 특정 기관 흉내 금지)
1. **표 길이**: 최대 40행 (분포: 짧은 표 유지 + 20~40행 25%)
2. **세로선 없는 스타일**: 가로줄만 / 헤더 아래 굵은 선 / 점선 세로 구분 — 기존 스타일과 섞어서
3. **빈 왼쪽 위 칸** (stub 헤더 없음) 30%
4. **L자형 헤더** (상위 항목이 자기 열 + 하위 열 위를 덮는 모양) — 라벨 규칙은 014와 동일
5. **구역 제목 행**: 라벨만 있고 값이 빈 행 / 전체 열을 덮는 colspan 행
6. **목록·문장형 표**: 열 2~4개, 긴 문장·코드 ID·글머리표(`·`, `-`) 여러 줄 셀
7. **자간 라벨**: CSS `letter-spacing`으로 렌더링만 벌리고 정답은 붙여 씀 (009의 라벨 불일치 수정)
8. **분류 열 들여쓰기**: 같은 열 안에서 하위 항목을 들여쓰기 (별도 열이 아님)
9. 기존 템플릿·스타일(원본·보강)은 그대로 유지하고 v3를 **추가**

## 27B 증류 방법 (지금 고정)
- **교사**: Qwen3.8-27B zero-shot, 입력 긴 변 1280 (test-real 0.985, test-real-2 0.971로 가장 정확)
- **풀**: 공공누리 제1유형이 확인된, test 문서와 겹치지 않는 공공 PDF 여러 기관. 표 검출은 Docling 레이아웃.
- **필터** (정답이 없으므로 신뢰도로 거름):
  1. 출력이 정상 종료 (잘림 아님), 표 추출 가능, 격자 일관
  2. **PDF 텍스트 레이어와 대조**: 27B 출력의 비어 있지 않은 셀 텍스트 중 페이지 원문에 (공백 무시) 들어 있는 비율 ≥ 0.95
  3. 1×N 같은 사소한 표 제외 (2행 미만 또는 2열 미만)
- 증류 표 중 일부(문서 단위로 분리한 ~40개)는 학습에 쓰지 않고 **라벨 없는 선택용 dev**로 둔다 (잘림 검사만).
- 혼합 비율: 증류 데이터는 2배 반복(소량·고가치) — 결과 문서에 실제 개수 기록.

## 체크포인트 선택 규칙 (009c 확장)
500 iter 간격 체크포인트마다: ① 합성 val(원본 val 100 + v3 val 100) TEDS ② **라벨 없는 실제 dev**(기존 17 + 증류 풀 dev ~40) 잘림 수 → 잘림 0 중 ① 최고. test 계열은 선택에 쓰지 않는다.

## 최종 평가와 판단 기준 (미리 선언)
- 모든 후보: test·ood(합성), test-real, test-real-2, 스캔 모사, + test_v3(긴 표 포함 합성).
- **test-real-3은 마지막에 한 번**: Docling, 2B zero-shot, 기존 최종(009c), A0, 새 최종(B 또는 C 중 선택 규칙으로 고른 것), 27B.
- 성공 기준:
  1. 새 최종이 test-real-2에서 **2B zero-shot(0.900)을 넘는다**
  2. test-real에서 기존 최종(0.956) 대비 **0.01 넘게 떨어지지 않는다**
  3. test-real-3에서 2B zero-shot과 기존 최종을 **모두 넘는다**
  4. 27B와의 격차를 보고한다 (넘는 것은 기준이 아님)
- 기준을 못 넘어도 결과는 그대로 보고한다.
